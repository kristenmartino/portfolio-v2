## Overview

Valuate is a portfolio prototype for exploring company valuations from SEC 10-K filings. It combines structured XBRL data with AI extraction for missing figures. Users can inspect source details, correct flagged values, and change assumptions to see how the estimate responds.

The company picker includes 18 sample tickers across five model categories. A free-text ticker entry supports exploring other 10-K filers, with limited extraction and model coverage.

## The problem

A valuation can calculate correctly while relying on the wrong input. SEC filers use different XBRL concepts for similar figures, and some required values are available only in filing text. The product needs to expose those extraction choices so a reviewer can examine the inputs before relying on the estimate.

Three decisions shaped the workflow.

## 1. Keep partial extraction results

The first extraction stage queries SEC XBRL company facts using a concept map. It returns the values it finds and leaves missing fields for Claude to extract from the filing's financial-statements section. Required fields still missing after the fallback and supported calculations produce an explicit error.

This matters because failing on the first missing XBRL field would prevent the fallback from running. In the original ten-company sample, three needed AI extraction or a calculated fallback. That observation describes this sample; it does not establish a market-wide coverage rate.

## 2. Show how each value was obtained

Each line item identifies its source: SEC XBRL, AI extraction, calculation, or user correction. Source details show an XBRL concept, an extracted excerpt, or a calculation explanation where available. These details support manual review; an excerpt alone does not establish that a value is correct.

Automated checks flag extraction scores below 0.80 and balance-sheet discrepancies above 0.5%. The scores are heuristics: XBRL scores reflect tag priority, while AI scores are model-reported. They are not calibrated probabilities of correctness, and an absence of flags does not mean a person verified the data.

A reviewer can replace a flagged value and optionally supply a supporting excerpt. Validation then runs again. The stored company record retains the current correction and its source label; it does not provide reviewer identity or a chronological edit history. Storage depends on deployment configuration: Postgres when configured, otherwise a process-local cache.

The Claude miss was an omitted pre-tax-income value. The small AI sample is a material limitation; the combined result should not be interpreted as general AI extraction accuracy. This is a historical baseline, not a new evaluation run.

The code includes deterministic valuation tests and correction tests across statement variants. One network-gated integration test exercises a real Apple filing. These checks cover specific behaviors, rather than every supported filer or financial model assumption.

The remaining limits affect how the tool should be used. Unclassified companies fall back to the standard DCF even when that model may not fit. Older periods can have incomplete field coverage. The energy model uses a fixed ten-year horizon rather than a company-specific reserve forecast. Filing freshness, broader extraction evaluation, and correction history need further work before this could support a production research workflow.
