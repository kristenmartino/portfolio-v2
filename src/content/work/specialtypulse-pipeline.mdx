## What I built

I built SpecialtyPulse to compare Medicare payments across specialties, inspect procedure-level differences, and test example access policies. The public demo uses sample reimbursement data and synthetic sales and usage records.

## A walkthrough

In the [demo](https://specialtypulse.kristenmartino.ai), Dermatology has the highest pressure score at 62.8. Its synthetic sales pipeline contains 53 active deals worth $4.58M—11.4% of the total. The summary puts those observations together and links to the underlying views.

Opening Dermatology's procedures shows the ten most-used services, ranked by service count. Each row includes the procedure description, HCPCS code and average Medicare payment. Changing the specialty updates the procedure list, flagged rows and trend charts.

The pressure score is a project-defined comparison measure. Its weights have not been validated against sales outcomes.

## How the data moves

PySpark notebooks load CSV values as text, cast and normalize them in staging, then aggregate a reporting table by specialty, procedure and year. Airflow sequences the notebooks with retries. A shared Python module defines columns, suppression rules and validation thresholds.

The Domo integration uploads the reporting table and defines output access policies. The standalone React build calculates its benchmarks from a bundled sample, so the demo can run after the Domo trial ended.

## One implementation tradeoff

The notebooks validate a temporary reporting table before replacing the previous version. That catches bad output before publication, but the drop-and-rename step leaves a brief availability gap. An operational deployment would need an atomic replacement or a view switch.

Metric definitions document the formulas and alternatives. Policy scripts check the example role configuration; CI runs live checks only with Domo credentials and otherwise checks syntax. The public demo displays illustrative policy results and does not enforce Domo access controls.

Next I would validate the pipeline against complete source releases, test access as each intended role and evaluate the pressure score against actual CRM outcomes. [GTM Healthcare Intelligence](/work/gtm-healthcare) covers the related reporting-workflow prototype.
