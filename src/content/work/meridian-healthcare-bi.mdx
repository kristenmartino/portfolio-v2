## The reporting question

Which clinics are furthest from their goals, which metrics explain the gap, and how does the answer change across markets and reporting periods?

Meridian is an independent reporting project for a fictional primary-care operator, using synthetic healthcare operations data. It combines a Power BI report, SQL/dbt transformations, a shared metric dictionary, and reconciliation checks.

The screenshots below are Power BI Desktop captures from October 23–24, 2026, cropped to the report canvas. They show the June 2026 reporting period using synthetic healthcare operations data. Open any image to inspect it at full resolution.

## Start with the reporting scope

The Overview shows performance for the selected market, clinic and period. Its category table identifies the metric furthest from goal in each category, while the headline cards summarize the selected population.

The metric-changes panel has its own comparison: June versus March. “Relative improvement” measures change relative to the earlier value, with the sign adjusted for whether higher or lower is better. It is a percentage change, not a percentage-point difference, and stays fixed when the period or comparison selection changes.

## Compare metrics and clinics

All metrics places actual, goal, comparison, trend and status in one table. The comparison column names its baseline. A positive value means above that baseline; a negative value means below it. Whether that is favorable depends on the metric’s direction. Status always uses the goal, even when the comparison changes to a prior period.

## Identify clinics to review

Needs attention shows up to five clinic exceptions for the latest month. The supporting model compares clinics with peers for the same metric, accounts for whether higher or lower is preferable, and selects each clinic’s most adverse eligible metric. Ranks remain global when a market or clinic filter is applied.

A flag identifies something to investigate. It does not establish the cause, clinical impact or a financial outcome.

## Make the rules inspectable

Metric definitions contains 17 catalog entries, including the operational measures, attributed members and Star composite. Each entry documents its definition, calculation, reference goal, direction and roll-up rule. Sources, owners and refresh cadence are illustrative. Financial assumptions support the illustrative financial scenarios.

The status guide explains the report’s rules. Watch allows up to 5% below goal when higher is better, or 6% above goal when lower is better. Those tolerances are relative to the goal, not percentage points. Missing actual or goal values receive no rating.

## Keep the numbers consistent

For rate metrics, the data model stores the numerator and denominator. Clinic, market and enterprise values are calculated from the summed components, rather than by averaging percentages. The SQL/dbt models and Power BI measures use the same calculation rule.

Data-layer checks cover relationships, allowed values and reconciliation across reporting levels. Native Power BI checks compare measure results with independently calculated expected values, including missing inputs, valid zero values, zero baselines and status boundaries. Report checks also covered period and comparison selections, filter carryover, drill-through, Back navigation and long-text rendering.

Accessibility metadata includes descriptions, reading order and decorative exclusions. Manual keyboard traversal and screen-reader testing remain incomplete.

## What the project demonstrates

Meridian demonstrates report design, metric documentation, dimensional modeling, DAX filter behavior and reconciliation using a controlled dataset. Operational and clinical outcomes have not been measured. Financial figures come from illustrative financial scenarios.
