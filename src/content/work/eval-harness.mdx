## What I built

I built a Python evaluation harness to compare language models on [Sift](/work/sift)'s news-processing tasks. The harness and methodology are available; the comparison on the real news corpus has not run, so there are no model rankings or routing recommendations yet.

## How a run works

Model adapters expose a shared interface. Task modules supply prompts, parse responses and calculate scores. The runner records inputs, model settings and outputs in JSONL files so interrupted runs can resume.

Categorization and summarization modules are implemented. Structured extraction and grounded question answering are planned. The study design covers nine models and keeps output quality, response time and cost separate for each task.

For pairwise summarization, judge selection avoids assigning an Anthropic model to judge pairs containing an Anthropic candidate. This addresses direct self-judging; it does not remove every source of judge bias. The design also includes an overlap sample for comparing judges and Bradley-Terry ranking of pairwise results.

## Keeping final scoring separate

The runner requires an explicit flag before using held-out data and checks its contents against a SHA-256 manifest. A sample lock and tamper-detection tests exercise that mechanism. The real corpus still needs to be collected, split and locked before prompt tuning.

A committed hash checks for changes to the dataset. Prior inspection is outside that check.

## Testing agent runs

A second track records an agent's tool calls, arguments, recovery from errors and final answer. Recorded runs support tests without API keys; checks that require a model judge use a separate live path. Fault and injection scenarios exercise failure handling.

These tests cover the evaluation machinery; model performance awaits a run on Sift's real corpus.

## What remains

The next steps are to prepare the corpus, measure local-model throughput on the DGX Spark, complete the remaining task modules and run final scoring. Until those runs are complete, the project demonstrates evaluation infrastructure and study design. Quality rankings, measured cost comparisons and model-selection decisions remain pending.

The [methodology site](https://evals.kristenmartino.ai/methodology) contains the detailed study plan; the [repository](https://github.com/kristenmartino/eval-harness) contains the implementation.
