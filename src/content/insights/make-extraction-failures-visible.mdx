In [Tenancy](/work/tenancy), an extracted field can include a page number, a snippet and coordinates for highlighting the source. Those references give a reviewer somewhere to look. They do not establish that the extracted value is correct.

Two details in the implementation matter:

- The extraction schema permits `source: null`. A field can arrive without a reference.
- The Q&A prompt requests citations, but the response schema permits an empty citation list. Parsing a valid response does not check whether the cited field supports the answer.

That distinction changes how I describe the feature: source navigation is implemented; independent citation verification is not. The [extraction schema](https://github.com/kristenmartino/tenancy-api/blob/main/schemas.py) and [Q&A handler](https://github.com/kristenmartino/tenancy-api/blob/main/qa.py) show the boundary.

The review queue addresses a different task. A person can accept a flagged value, save a correction or reject it. Extractions are already stored before those decisions. Clearing a blocker records a review decision; it is not an accuracy measurement.

The next evaluation needs labeled leases with expected values and supporting source locations. I would score value correctness and source support separately, including missing fields and incorrect references. A working page link should not turn either failure into a pass.
